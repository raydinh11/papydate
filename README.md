# Papy-Date: timeline embedding for Greek papyrus dating

This repository contains the training and inference code for the experiments in
*Timeline Embedding for Papy-Date, a New Dataset of Greek Papyri Dated to the
Year*. The work introduces Papy-Date, a dataset of 1,560 Greek papyri represented
by 2,168 images and dated between 279 BCE and 796 CE, and studies a sinusoidal
timeline embedding with a contrastive objective for image-based dating.

The paper has been accepted at the
[ICDAR 2026 Workshop on Computational Paleography (IWCP, 4th edition)](https://www.csmc.uni-hamburg.de/iwcp2026.html).
Its official proceedings record is not yet available; see [Citation](#citation)
for an interim reference.

## What is included

The repository covers the model-training and prediction stages of the paper:

- four-stream crop input: RGB and binarized (DPL), at letter and context scales;
- a ResNet-18 crop encoder and sinusoidal timeline representation;
- regression, one-year classification, one-century classification, timeline
  cross-entropy, and timeline contrastive training targets;
- checkpoint creation and per-crop prediction export; and
- helper functions for crop- and heatmap-level aggregation.

The dataset images, prepared crop caches, cache-generation pipeline, and
pretrained checkpoints are not included in this repository. Training therefore
requires the precomputed Papy-Date caches described below.

## Requirements

- Python 3.10 or newer
- A CUDA-capable GPU and a CUDA-enabled PyTorch installation for the provided
  configurations

Assuming [`uv`](https://docs.astral.sh/uv/) for environment management, create an environment and install the runtime dependencies:

```bash
git clone https://github.com/raydinh11/papydate.git
cd papydate

uv venv --python 3.10
source .venv/bin/activate
uv pip install numpy opencv-python pillow pyyaml torch torchvision tqdm
```

PyTorch installation depends on the operating system and CUDA version. If the
command above does not select the correct build, use the command generated by
the [official PyTorch installation guide](https://pytorch.org/get-started/locally/)
inside the same environment.

The default configurations use ImageNet-pretrained ResNet weights, which
Torchvision downloads on first use. For an offline run, provide the weights in
Torch's local cache or set `rn_pretrained: false` in the selected configuration
(the latter does not reproduce the paper setup).

## Data layout

The supplied configurations expect `benchmarks/papydate/` to contain four
precomputed crop caches:

| Cache                                | Paper stream                    |
|--------------------------------------|---------------------------------|
| `cache_papytwin_letters2`            | RGB letter crops (RGB-L)        |
| `cache_papytwin_letters2_dpl`        | Binarized letter crops (DPL-L)  |
| `cache_papytwin_letters5_layout`     | RGB context crops (RGB-C)       |
| `cache_papytwin_letters5_layout_dpl` | Binarized context crops (DPL-C) |

Each cache must provide the following split structure:

```text
benchmarks/papydate/
└── <cache-name>/
    ├── train/
    │   ├── index.json
    │   └── chunks/*.npy
    ├── val/
    │   ├── index.json
    │   └── chunks/*.npy
    └── test/
        ├── index.json
        └── chunks/*.npy
```

`index.json` stores document metadata and the location of every crop in the
NumPy chunk files. The loader expects each crop record to identify its chunk
file, offset, source-document index, Trismegistos identifier, spatial position,
and ink ratio. Document metadata must include at least the date and
Trismegistos identifier; image dimensions and image identifiers are also needed
to export spatial predictions.

To use another location or a different set of caches, change `dataset.root` and
`dataset.cache_dir_name` in the chosen YAML configuration.

## Run an experiment

The proposed timeline-contrastive experiment is the main entry point:

```bash
python train.py --cfg configs/cfg_timeline_contrastive.yaml
```

Training creates a timestamped directory under `runs/` containing a
configuration snapshot, `cfg.yaml`, and the latest checkpoint, `end_eps.pt`.
Use `--ckpt-root` to choose a different output directory.

The available experiment configurations are:

| Configuration                           | Training target                                                                 |
|-----------------------------------------|---------------------------------------------------------------------------------|
| `configs/cfg_timeline_contrastive.yaml` | Timeline embedding with image-to-timeline and image-to-image contrastive losses |
| `configs/cfg_timeline_ce_dot.yaml`      | Timeline embedding with cross-entropy                                           |
| `configs/cfg_regression.yaml`           | Scalar regression baseline                                                      |
| `configs/cfg_ce_year.yaml`              | One-year classification baseline                                                |
| `configs/cfg_ce_century.yaml`           | One-century classification baseline                                             |

All supplied configurations target CUDA. To run on CPU, set `train.device` to
`cpu`; mixed precision is then disabled automatically, but training will be much
slower.

## Export predictions

After training, export per-crop predictions for the validation and test splits:

```bash
python tools/dump.py --ckpt runs/<experiment-timestamp>/end_eps.pt
```

This writes `per_crop_val.json` and `per_crop_test.json` beside the checkpoint.
Use `--out`, `--root`, `--caches`, or `--splits` to override those defaults; run
`python tools/dump.py --help` for the complete interface.

`tools/agg.py` contains the crop voting and heatmap pooling functions used by
the experiment analysis. It is a helper module rather than a command-line
program.

## Repository structure

```text
configs/    Experiment definitions
dataset/    Crop-cache loading, sampling, and augmentation
losses/     Timeline and baseline training objectives
model/      Encoder, timeline representation, and checkpoint loading
tools/      Prediction export and aggregation helpers
train.py    Training entry point
trainer.py  Optimization and validation loop
```
